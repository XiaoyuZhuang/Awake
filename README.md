**Awake 的核心操作很简单：每点一次，就给当前倒计时增加一段时间，默认是 10 分钟。** 用桌面“Awake 加时”快捷方式即可直接加时，不打开应用界面；剩余时间显示在常驻通知中。时间到了之后，默认每 10 秒提醒一次，直到你增加时间或停止。

## 开发初衷

### 从“做了多久”，回到“准备做多久”

我们经常刷视频或者学习，一不小心就做了很久。沉浸在一件事情里时，很容易忘记时间，也容易忘记喝水、休息和照顾自己的身体。其实，身体才是最重要的，我们应该留意喝水之类的事情，给自己留一点停下来照顾身体的时间。

我更想要的是一种类似于番茄钟的体验。我在拼多多上看到一种叫“转一圈”的番茄钟：只要转一圈，就能转到对应的时间，开始倒计时。这个动作很直接，也很自然，不用为了开始计时，先完成一连串操作。

Awake 就是想做成这个样子：**点一下，就增加 10 分钟倒计时；在没有正在进行的倒计时，或者上一段时间已经结束时，点一下，就有了接下来的 10 分钟。** 这样，我们心里就会一直有一个“10 分钟的计划”，知道接下来准备做什么，也知道到底要做多久。

比如学习时，我就点 3 下，给自己大约 30 分钟的学习时间。学习时间到了，我就再点一下，休息 10 分钟。接下来要继续学习，就再给自己安排一段时间。一直保持着倒计时，防止自己不小心沉浸在某个事情里面，一做就忘了多久。

我觉得这个思路非常好，所以就做了这个东西。它想带来的，是一种能随时开始、能随时延续的时间感：做事情之前，先给这段时间一个简单、明确的计划。

> 当前倒计时还没结束时，再点一次会在剩余时间上增加 10 分钟；不会把剩余时间重置为 10 分钟。单次增加的时长也可以自己调整。

### 让开始倒计时变成一个随手的动作

如果手动开启倒计时，步骤可能会很复杂：打开工具、选择时间、确认，再开始。大家都知道倒计时，也知道它有用，但有时候步骤太复杂了，就会让人不想去倒计时，或者觉得这个过程没有想象中那么优雅。

我希望我们的软件操作更简单：只需按个按键，选择一下时间之类的，就能把计时绑定到一个随手可以触发的入口上。在 Awake 里，先选择好每次增加的时间，再把加时快捷方式放到桌面，之后只需点一下，就能开始或延长倒计时，不用每次重新设置时间。

### 追求极致轻量，也追求使用时的好感觉

软件一定要轻量，必须能快速进行倒计时。计时这件事情本身不复杂，开始计时的动作也应该足够简单，让人愿意反复使用。

我希望有了这个软件，倒计时本身仿佛就是一种快感、一种很好的感觉，是一种很爽的感觉：随手点一下，把这段时间安排好，然后就开始去做这件事。大概就是这个意思。

**让“开始倒计时”成为一个舒服、直接、愿意去做的小动作，正是 Awake 的设计初衷。**

## 快速开始

### 1. 安装

从 [📦 最新 Release](https://github.com/XiaoyuZhuang/Awake/releases/latest) 下载 `Awake-release.apk` 并安装。需要 **Android 8.0 或更高版本**。

首次点击应用图标，会增加默认的 10 分钟倒计时，并进入设置页面。请允许通知权限，让剩余时间和设置入口显示在通知栏中。

### 2. 设置一次，之后随手点

在设置页面中，选好“每次启动增加的分钟数”，默认是 10 分钟。推荐点击 **“添加桌面加时快捷方式”**，在系统确认后，将 **“Awake 加时”** 放到桌面。

此后点击这个快捷方式，就直接增加时间，不打开设置页面。加时后会显示底部短提示，常驻通知同时更新剩余时间，不额外弹出加时临时通知。

原应用图标的行为由“进入方式”控制：

| 入口 | 行为 |
| --- | --- |
| 桌面“Awake 加时”快捷方式 | 直接增加时间，不打开设置 |
| 原应用图标 · 每次启动后进入设置 | 增加时间，然后打开设置；新安装默认使用此方式 |
| 原应用图标 · 仅通过通知进入 | 增加时间，不打开设置 |
| 常驻通知正文 | 打开设置，不增加时间 |
| 通知中的“增加时间”／“停止” | 直接执行对应操作 |

### 3. 给当前事情安排一段时间

以默认每次 10 分钟为例：

| 我准备做的事情 | 随手操作 | 计划 |
| --- | --- | --- |
| 看一会儿视频 | 点 1 下 | 先安排 10 分钟，到时提醒自己停一下 |
| 学习一段时间 | 连点 3 下 | 从未启动状态开始，安排大约 30 分钟 |
| 学习结束后休息 | 到时再点 1 下 | 开始下一段 10 分钟的休息 |
| 暂时不需要计时 | 点击“停止倒计时” | 停止倒计时和持续提醒 |

设置页面顶部也会实时显示剩余时间，下面并排放置 **“立即增加”** 和 **“停止倒计时”**，打开后就能直接操作。

时间用完后，默认每 10 秒通过独立的高优先级“到时提醒（横幅）”通知提醒一次，横幅短暂显示后自动消失，声音为短响。增加时间会结束当前提醒，并开始新的倒计时；点击停止则结束倒计时和提醒。学习与休息之间的切换由你自己点击决定。

## 功能与设置

| 设置 | 默认值 | 可自定义内容 |
| --- | --- | --- |
| 每次启动增加的时间 | 10 分钟 | 1–1440 分钟 |
| 到时提醒间隔 | 10 秒 | 1–3600 秒 |
| 震动 | 开启 | 加时与到时提醒的震动反馈 |
| 声音 | 开启 | 到时提醒的声音反馈 |
| 到时通知 | 开启 | 是否显示倒计时结束后的提醒通知 |
| 设置页面入口 | 每次启动后进入设置 | 每次启动后进入设置／仅通过通知进入 |
| 界面语言 | 简体中文 | 简体中文／English |
| 界面主题 | 跟随系统 | 跟随系统／浅色／纯黑夜间主题 |

- **常驻倒计时通知**：由本地前台服务维护，显示剩余时间，并提供设置、加时和停止入口。“到时通知”开关单独控制结束后的提醒通知。
- **紧凑设置页**：顶部显示实时倒计时，加时／停止、震动／声音、语言／主题分别并排，减少来回滑动。
- **桌面快捷加时**：使用无显示界面入口，减少启动界面和动画带来的打断。
- **后台运行设置**：提供通知权限和系统电池设置入口，方便允许后台运行。
- **本地保存状态**：倒计时截止时间和个人设置保存在本机，服务恢复时会读取保存的状态。
- **检查更新**：先比较版本，有更新才询问是否打开发布页；没有更新时提示“已经是最新版本”。

## 常见问题

### 需要谷歌服务或联网吗？

日常倒计时、震动、声音和常驻通知在手机本地运行，**不依赖 Google Play 服务或谷歌推送，也不需要联网**。检查更新和下载安装新版 APK 时需要访问 GitHub。

### 为什么安装后默认会进入设置？

第一次使用时，需要让用户容易找到时长、提醒间隔和通知权限。默认每次启动后进入设置，方便上手；熟悉以后，可以自己选择“仅通过通知进入”，或使用桌面加时快捷方式。

### 到时有声音，却没有横幅怎么办？

到时提醒使用独立的“到时提醒（横幅）”通知分类；加时只显示底部短提示，常驻倒计时通知保持静默。在设置页点击“到时横幅设置”，可以直接打开这一分类的系统设置，允许横幅／悬浮通知和锁屏显示。勿扰模式、系统通知冷却或厂商的通知策略仍可能限制连续横幅，具体行为以手机系统为准。

### 手机锁屏后还能提醒吗？

应用通过本地前台服务和常驻通知在后台运行。部分手机仍会限制或清理后台应用，可以允许通知、开启系统自启动，并将电池使用设置为不受限制。设置页提供“通知权限”和“后台运行设置”入口，具体选项名称以手机系统为准。

### 更新后会丢失设置吗？

从 Releases 下载 `Awake-release.apk`。使用同一签名的 Release 版本可以直接覆盖安装并保留设置。Debug 和 Release 的签名不同，不能互相覆盖安装。

设置页中的“检查更新”会读取最新 Release 的版本信息：有较新版本时先询问是否打开发布页，没有更新时提示已是最新版本；网络访问失败时提示重试。

### 会收集个人信息吗？

无需账号，不收集个人信息。倒计时状态和设置保存在本机；应用仅在主动检查更新时访问 GitHub。

## 构建与发布

项目使用 Kotlin、Android SDK 和 GitHub Actions 构建。构建配置为 **最低 Android 8.0（API 26）**、**编译／目标 API 35**、**JDK 17** 和 **Gradle 8.9**。

推送到 `main` 或手动运行 [Build APK 工作流](https://github.com/XiaoyuZhuang/Awake/actions/workflows/build.yml)，会执行 Debug 编译、Lint 检查和 Android 15 界面验证，构建产物可在 Actions 中下载。界面验证覆盖桌面加时、通知入口、实时倒计时、加时／停止、桌面快捷方式以及停用谷歌服务后的本地运行，并保存测试截图。文档专用提交可使用 `[skip ci]` 跳过构建。

在仓库的 **Settings → Secrets and variables → Actions** 中配置以下 Repository Secrets 后，工作流还会构建签名 Release APK，并自动发布到 [Releases](https://github.com/XiaoyuZhuang/Awake/releases)：

| Secret | 内容 |
| --- | --- |
| `KEYSTORE_BASE64` | 签名 keystore 文件的完整 Base64 内容 |
| `KEY_ALIAS` | 签名密钥别名 |
| `KEYSTORE_PASSWORD` | keystore 密码 |
| `KEY_PASSWORD` | 签名密钥密码 |

版本号在 `app/build.gradle.kts` 和 `version.json` 中维护，发布新版本时需同步更新，并递增 `versionCode`。请保管好签名密钥，不要将 keystore、密码或其 Base64 内容提交到仓库。
